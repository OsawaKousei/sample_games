# Survivor の難易度調整

## 目標と設計

初回から安全に立ち続けられる構成を改め、壁で敵を分断し、高台で撃破と経験値を稼ぎ、補給地点を回る経路を覚えて攻略するゲームにする。単純な敵数の増加だけで難しくせず、経路と強化の選択に結果の差を作る。

- **序盤から移動が必要**：初期攻撃は16ダメージ／0.72秒、追跡敵は42 HP。左右から接近する最初の2体は自動射撃だけでは処理しきれない。7秒以降に突進敵、18秒以降に射撃敵が加わる。
- **壁を使った切り返し**：6つの障害物が移動と双方の弾を遮る。通常敵は迂回し、突進は衝突すると1.7秒気絶する。回避ステップも壁をすり抜けない。
- **高台に登る理由**：2つの高台は射程 +4・威力 +20%。登り坂は自機より追跡敵を強く減速する。中央のぬかるみは自機の速度を32%、敵を13%下げるため、短絡路には危険がある。
- **補給を取りに行く理由**：結晶は8秒後から20秒ごとに4地点を巡回し、28秒で消える。回復12 HPは結晶と交互に出現する。強化は経験値でも取得できる。出現の乱数シードは固定し、リトライで経路を改善できる。
- **強化の選択**：火力は攻撃力・攻撃間隔・貫通、機動力は移動速度・回避の再使用時間、耐久力は最大体力・10 HP回復・軽減率。火力8回、機動力3回で上限。耐久力の軽減率は20%まで。選択中はゲーム時間が止まり、複数報酬も取りこぼさない。
- **後半の圧力**：敵の出現間隔は0.85 → 0.62 → 0.43秒。射撃は1 → 3 → 5方向に広がり、PHASE 3で重装敵が加わる。突進は0.8秒、射撃は0.9秒の予告があり、最後の0.35秒は狙いを固定する。予告線も壁で遮られる。

自機を遮る壁は半透明にし、位置を示す輪は障害物の裏でも表示する。描画と衝突判定は同じ障害物定義を使い、物理更新は描画速度によらず60 Hzで行う。

## 評価方法

実ゲームの `model.js` と `field.js` をそのまま動かす。生存時間、初被弾時刻、被弾数、残り体力、撃破数、強化数、高台・ぬかるみの滞在時間、障害物による弾の消滅数、突進の衝突数を記録する。

標準操作は **0.5秒ごとに判断し、0.2秒後に反映、次の反映まで入力を保持**。物理だけを60 Hzで更新する。候補は停止、8方向の移動、再使用可能な場合の8方向の回避。強化選択中は物理時間が止まるので、選択時間は生存時間に含めない。この0.2秒は評価用の仮定で、人間の反応時間を実測した値ではない。

| 方策 | 内容 |
| --- | --- |
| 静止 | 移動・回避をしない |
| 単純な周回 | 一定周期で8方向の入力を回す。近距離に敵がいると回避する。地形の経路計画は行わない |
| 地形経路 A | 壁の外、高台、補給地点を経由する8地点の経路。近くの報酬と危険を見て候補を選ぶ |
| 地形経路 B | 最初の目的地は同じで、その後の巡回順を逆にする |

経路の自動操作は約0.7秒先まで敵・弾との接近を評価する簡易制御で、探索による完全解ではない。画面外を含む敵の座標を知っている点では人間より有利。一方、予測は単純で、突進の追尾中の狙い変更などは正確には予測しない。視認性、学習、操作ミス、心理的負荷は評価できない。

通常のシードは314159。追加4シードは頑健性の診断用で、プレイ時に毎回シードが変わる仕様ではない。`stunnedCharges` は岩壁と外周への衝突の合計、`blockedBolts` は壁に当たった弾全体であり、「地形がなければ被弾した回数」を表すものではない。

## 測定結果

実測の全件とソースハッシュは [difficulty-results.json](difficulty-results.json)。標準シードで、状況に応じて火力・機動力・耐久力を選ぶ方策の結果：

| 方策 | 生存時間 | 結果 | 残り体力 | 撃破 | 強化 |
| --- | ---: | --- | ---: | ---: | ---: |
| 静止 | 17.17秒 | 敗北 | 0 / 100 | 5 | 0 |
| 単純な周回 | 44.95秒 | 敗北 | 0 / 100 | 8 | 0 |
| 地形経路 A | 103.08秒 | 敗北 | 0 / 116 | 36 | 4 |
| 地形経路 B | 135.00秒 | クリア | 30.72 / 132 | 87 | 9 |

静止の初被弾は5.72秒。5シードでは静止・単純周回はすべて敗北し、経路 A は2/5、経路 B は3/5でクリアした。**これは自動操作の結果で、人間の初見クリア率ではない。**

経路 B の強化方針を変えた標準シードでの比較：

| 強化方針 | 生存時間 | 残り体力 |
| --- | ---: | ---: |
| 火力を優先 | 71.62秒 | 0 / 100 |
| 機動力を優先、上限後は耐久力 | 135.00秒 | 66.48 / 132 |
| 耐久力のみ | 118.18秒 | 0 / 140 |
| 火力 → 耐久力 → 機動力の順で繰り返す（上限後は耐久力） | 135.00秒 | 69.92 / 124 |

攻略経路は一つに限定されず、強化方針によって余裕のあるクリアも存在する。残り体力が常に僅少になるような結果への補正は行わない。

## タイミングの感度と限界

保存した経路 B の操作記録を、敵の情報を見ずに再生して135秒生存できることを回帰テストにした。ただし全入力を一律0.1秒早めると75.10秒、遅らせると82.28秒で敗北する。これは敵の誘導や報酬回収の差が最後まで累積する再生であり、人間に0.1秒未満の操作精度が必須だと示す実験ではない。それでも、タイミングの感度が残る点には注意して調整する。

状況を見て毎回判断し直す経路 B でも、判断・反映の間隔を変えて評価した。予測器は標準の0.2秒遅延を前提のままにし、実際の入力反映と保持時間だけを変更している。

| 反映遅延 | 判断間隔 | 生存時間 | 残り体力 |
| ---: | ---: | ---: | ---: |
| 0.1秒 | 0.5秒 | 65.25秒 | 0 / 124 |
| 0.2秒 | 0.4秒 | 135.00秒 | 29.04 / 140 |
| 0.2秒 | 0.5秒 | 135.00秒 | 30.72 / 132 |
| 0.2秒 | 0.6秒 | 89.12秒 | 0 / 116 |
| 0.3秒 | 0.5秒 | 90.85秒 | 0 / 124 |

毎フレームの超人的な方向転換に依存しない攻略例は確認できた。一方、これだけで人間にとっての公平性や初見難易度を確定できない。実プレイでは初回と反復後の生存時間、被弾直前に予告を視認できたか、壁際で切り返せたかを確認する。初見クリア率の目標については人間のプレイテストが未実施。

## 今後の調整の順序

1. 静止や単純周回が安定して通用する場合、初期敵の到達時間・補給地点・射線を先に見直す。
2. 学習済み経路でも攻略不能なら、予告の固定時間、壁間の通路幅、突進後の隙を先に確認する。敵数や体力を一律変更しない。
3. 一つの強化が常に有利なら、単系統と混合の撃破・被弾・補給取得を比較して調整する。
4. 変更後は静止・周回・地形経路・強化方針・操作間隔をまとめて再測定し、都合のよいクリア例だけを採用しない。

## 再実行

リポジトリのルートから：

```sh
npm test --workspace @arcade/survivor
npm run --silent difficulty --workspace @arcade/survivor > /tmp/survivor-difficulty.json
npx playwright test survivor/src/game.browser.spec.js
npm run build --workspace @arcade/survivor
```

通常の評価は保存済みの攻略記録を書き換えない。難易度変更を検証したうえで記録も更新する場合のみ、`node survivor/tools/measure-difficulty.mjs --record` を使う。クリアできなければ記録を上書きしない。
