# 難易度の評価

スクリーンショットや弾数だけで調整せず、「攻略を知る前の探索」「覚えた後の操作負荷」「入力誤差への余裕」を分けて測る。STAGE 2を比較対象にするが、自動探索の成績を人間の成功率へ変換しない。

```sh
npm run measure:difficulty --workspace @arcade/shooter
npm run test:difficulty --workspace @arcade/shooter
```

全ボスフェーズの計測には数分かかる。出力は `shooter/reports/difficulty.json`。保存先を変える場合は `-- /tmp/difficulty.json` を付ける。生成日時、プロトコル、ゲームと計測コードのSHA-256、各試行の操作履歴・時系列・打ち切り時刻を保存する。レポートは生成物としてGit対象外。

## 操作の時間単位（schema 2）

物理計算・衝突判定は60Hz。**操作の判断と変更は下表の粗い時間単位に制限する。** 旧版も判断自体は300ms間隔だったが、即時反応の条件と30Hzの座標補間による攻略リプレイが混在していた。今回、そのリプレイを廃止し、反応待ちと入力保持を計測条件に含めた。

| 条件 | 判断後の反応待ち | ブロック内の新入力保持 | 判断間隔・入力変更の最短間隔 | 候補を検査する時間 |
| --- | ---: | ---: | ---: | ---: |
| responsive | 150ms | 250ms | 400ms | 550ms |
| standard（標準） | 200ms | 300ms | 500ms | 700ms |
| deliberate | 300ms | 400ms | 700ms | 1000ms |

標準条件では時刻0で判断し、200msまでは直前の入力を続け、200msで選んだ入力へ切り替える。次の判断は500ms、次に切り替えられるのは700ms。したがって新入力は実際には500ms以上保持される。候補評価も700msまで確認し、**次の判断後の反応待ちに当たる200msを省かない**。入力を保持している間の方向変更、低速切り替え、座標補間は許さない。実行した変更時刻もJSONで確認できる。

これらは反応と持続入力を考慮するための評価上の仮定であり、人間一般の反射神経を測った値ではない。150〜300msの反応待ちと400〜700msの判断間隔を比較して、条件への感度を見る。操作は停止＋8方向×通常／低速＝17候補。

## 指標と限界

| 指標 | 条件 | 読み方 |
| --- | --- | --- |
| 固定時間の無被弾 | X=120 / 240 / 360、Y=620から24秒。射撃・ボムなし、初回被弾で終了 | 24秒生存は撃破ではない。短時間で打ち切った試行の後半は未評価。 |
| 安全な固定操作の割合 | 17候補を反応待ち＋保持＋次の反応待ちまで本番の `tick()` で検査 | 0候補でも途中で曲がる攻略や長期計画までは否定できない。 |
| 停止候補の安全率 | 反応待ちの後で停止する候補の無被弾率 | 休止しやすさの補助指標。現在地で直ちに止まる条件とは異なる。 |
| 経路上の余白 | 実行中の当たり判定からの距離の下位10%、64pxで上限 | 画面全体の隙間幅ではない。0.1秒ごとの測定、衝突自体は60Hz。 |
| 静止射撃で突破 | X=80 / 160 / 240 / 320 / 400 × Y=500 / 620、最長60秒、HP5・火力3・通常の被弾後無敵・ボムなし | 回避せず耐久力だけで突破できる場所を調べる。 |
| 既知経路の誤差耐性 | 下記の保持入力リプレイを本番の物理で再生 | 操作可能な攻略例の確認。初見の発見難度や全開始条件の保証ではない。 |

局所探索は未来の発射予定と再照準も知っている。人間より有利な情報を持つ一方、長期計画を持たない。遅延を増やすと別の経路を選び、成績が改善する場合もある。生存時間や安全候補率を単一の「難易度点数」へまとめない。短時間で失敗した区間と24秒生存した区間の平均を、そのまま難易度順位にしない。

## 既知の攻略と誤差

`tools/replays.mjs` に保持入力の攻略例を保存した。弾は消さず、射撃・ボム・無敵も使用しない。

- フェーズ2：X=78、Y=620から開始。最初の輪には200ms後に反応し、その後は周期を覚えて直角に曲がる。通常移動400msで輪を抜け、低速で自機狙いを誘導する。40秒間検証。最短入力保持400ms。
- フェーズ3：X=240、Y=620から開始。開く順番を見越して四隅の弾塊の内側へ移り、次の展開に合わせて位置を変える。32秒間、5回の展開周期を検証。最短入力保持500ms。

入力時刻の一律ずれ−100 / −50 / 0 / +50 / +100msと、開始位置のずれ(0,0)、(−4,0)、(+4,0)、(0,−4)、(0,+4)の直積は、両フェーズとも**25/25条件で無被弾**。±200msもレポートに含めるが、成功する条件だけに絞って表示しない。これは全入力を一律にずらした試験であり、各操作に独立した誤差を加えた試験ではない。

| 既知経路 | −200ms（5開始位置） | ±100ms以内（25条件） | +200ms（5開始位置） |
| --- | ---: | ---: | ---: |
| フェーズ2 | 0/5 | 25/25 | 0/5 |
| フェーズ3 | 1/5 | 25/25 | 0/5 |

ボス移動位相2 / 5 / 8 / 11秒からも同じ経路を検査した。両フェーズとも4条件すべてで生存した。フェーズ3の弾塊はボス位置に依存しないため、ボスの移動に従って配置が崩れない。ただし、自機の開始位置を画面全域で検証したわけではない。

## 残る評価

- 既知経路への独立した操作時刻の揺らぎ、さらに複数の攻略方針を追加する。
- 発射予定を知らず、見えている弾と予告だけを使う探索と比較する。
- 道中の残留弾、前フェーズからの自機位置、火力1 / 3などの通常進行条件を広げる。
- 実プレイの入力・被弾地点・ボム・撃破時間を測り、学習後の操作負荷と自動指標の関係を確認する。

今回は道中を8秒へ短縮し、フェーズ3を四隅の弾塊へ差し替えた。フェーズ1の精密操作負荷やフェーズ4後半の重なりまで、均等に調整できたという結論ではない。参照元との対応は [STAGE 3](stage3-patterns.md) に記載する。
